# FASK 개인용 전환 계획

작성일: 2026-10-21. 상태: 개인용 첫 구현 반영. 아래는 목표 설계이며 현재 제공하는 범위와 후속 항목은 [PERSONAL_IMPLEMENTATION.md](PERSONAL_IMPLEMENTATION.md)를 참고한다. 기존 수업 DB는 변경하지 않았다.

## 1. 목표와 기본 결정

화면 위에서 질문하고, 답변과 맥락을 프로젝트별 개인 지식으로 축적하는 로컬 데스크톱 앱으로 전환한다.

- Electron + React + TypeScript, 투명 오버레이, 펜/지우개, 그래프 렌더링을 재사용한다.
- 교사/학생 역할, 수업 코드, 주차, 교사 전달, 실시간 수업, 수업 관련성 필터, recall quiz를 개인용 실행 경로에서 제거한다.
- 앱 로그인 대신 로컬 프로필을 둔다. 기본 프로필로 즉시 시작하고 필요할 때 추가한다.
- 계층은 `프로필 → 워크스페이스 → 프로젝트 → 질문/대화/개념`이다.
- AI 연결은 EasyCLIProxyAPI의 로컬 API endpoint를 기본으로 사용한다. 공급자 로그인·계정 연결은 EasyCLIProxyAPI에서 관리하고 FASK에는 endpoint와 필요한 로컬 접속 키만 설정한다.
- 질문 다듬기, 모델 추천/라우팅, 지식 정리는 독립 설정으로 둔다. JEV 연동은 보류한다.
- 로컬 저장·검색·수동 정리는 AI 연결 없이 동작한다. AI에 전송한 내용은 외부 공급자가 처리하므로 완전한 오프라인 AI는 아니다.

## 2. 현재 코드에서 확인한 재사용 범위

| 위치 | 현재 동작 | 전환 방향 |
|---|---|---|
| `desktop/src/main/overlay.ts` | 투명 창, 클릭 통과, 창 숨김 후 모니터 캡처 | 재사용. 세션/주차 인자를 프로젝트 문맥으로 교체 |
| `desktop/src/renderer/src/pages/student/OverlayPage.tsx` | 펜/지우개, Esc, 캔버스, 질문 패널 | 사용자용으로 변경, 영역 선택·단축키 추가 |
| `desktop/src/renderer/src/pages/student/overlay/QuestionPanel.tsx` | 다듬기 → 검토 → 수업 질문 등록 | 다듬기 생략, 답변 스트리밍, 후속 질문, 로컬 저장 |
| `desktop/src/renderer/src/components/MindMap/` | 개념 트리 표시 | 프로젝트 개념 보기로 재사용. 다중 관계 보기는 별도 보완 |
| `desktop/src/renderer/src/lib/trees.ts` | 주차/교사/학생에 의존하는 트리 구성 | 프로젝트·개념·질문 기반 변환으로 교체 |
| `desktop/src/renderer/src/App.tsx` | 토큰과 역할에 따른 라우팅 | 프로필·워크스페이스·프로젝트·설정 라우팅 |
| `desktop/src/main/profile.ts` | 실행 인자로 Electron userData 분리 | 일반 사용자 프로필 선택과 데이터 경로 설계에 참고 |
| `server/app/models.py` | 질문이 수업·주차에 필수 연결, 교사용 질문 복제 | 개인용 새 스키마 필요 |
| `server/app/services/refine.py` | 수업 문맥과 금지어/관련성 검사 | 선택적 다듬기만 새 서비스로 이전 |
| `server/app/services/classify.py` | 기존 강의 개념 후보 중 배정, 교사 복제/전달 | 프로젝트 내 개념 연결과 생성으로 재설계 |
| `desktop/src/renderer/src/lib/recall.ts` 등 | recall quiz | UI·타입·실행 경로에서 제거 |

현재 저장소는 질문을 교사에게 등록하며, 사용자에게 답변하는 대화 기능은 새로 구현해야 한다. UI 이름 변경만으로 전환할 수 없다.

## 3. 실행 구조

목표 구조:

```text
React 화면: 대시보드 / 투명 오버레이 / 설정
  → 제한된 preload IPC
  → Electron main 및 작업용 프로세스
      ├─ 프로필·워크스페이스·프로젝트 서비스
      ├─ SQLite 저장·검색·마이그레이션
      ├─ 캡처·이미지 보관
      ├─ 로컬 API 어댑터·접속 키 보호·스트리밍
      ├─ 추천 정책·비동기 지식 정리
      └─ 기억 내보내기 / 후속 MCP 어댑터
```

새 개인용 실행은 기존 FastAPI 서버를 요구하지 않는다. AI 기능은 사용자가 별도로 실행한 EasyCLIProxyAPI의 로컬 HTTP endpoint에 연결한다. DB 접근과 로컬 API 호출은 renderer에 노출하지 않는다. 오래 걸리는 이미지 처리·검색 작업은 UI를 막지 않도록 분리한다. SQLite 드라이버는 현재 Electron 런타임 호환성과 Windows 패키징을 작은 검증으로 확인한 후 확정한다.

기존 Python 서버 파일은 전환 중 비교·이관 참고용으로 보존한다. 개인용 실행이 완성된 뒤 불필요한 의존성을 정리한다. 배포 서버 제거와 AI 공급자에 대한 인터넷 통신은 별개다.

## 4. 프로필과 프로젝트

- 첫 실행: 기본 프로필과 기본 워크스페이스 생성. 회원가입 없이 진입.
- 한 프로필 아래 여러 워크스페이스, 한 워크스페이스 아래 여러 프로젝트.
- 프로젝트마다 설명, 용어, 기본 공급자/모델, 기억 공유 범위, 저장 정책을 설정.
- 전역 기본값 → 프로필 → 프로젝트 → 이번 질문 순으로 설정을 덮어쓴다.
- 오버레이에 현재 프로젝트를 항상 표시한다. 프로젝트 전환 시 진행 중 초안과 요청을 기존 프로젝트에 고정한다.
- 로컬 API 연결 설정은 프로필에 귀속하고 프로젝트에는 사용할 연결 ID와 모델을 지정한다. 실제 상위 공급자 계정과 인증 정보는 EasyCLIProxyAPI가 관리한다.
- 프로필별 DB·첨부 디렉터리를 분리하고 조회/작업에도 프로젝트 범위를 검증한다. 프로필 선택 자체는 OS 사용자 간 보안 격리나 DB 암호화를 제공하지 않는다.

## 5. 오버레이와 질문 흐름

기본 흐름:

```text
프로젝트 선택 → 화면 표시/영역 선택/질문 입력
→ 로컬 초안 저장 → [선택적 다듬기·검토]
→ 모델 추천 또는 사용자 지정 → 질문 전송
→ 작은 패널에서 답변·후속 질문
→ 로컬 기록 보존 → 비동기 분류·개념 연결
```

- 평소 화면은 투명하고 배경 앱 클릭·스크롤이 통과한다.
- 작고 이동 가능한 툴바: 펜, 지우개, 영역 선택, 질문, 대시보드, 종료.
- 패널은 기본 접힘. 열었을 때 위치·크기 변경 가능하며 그림 모드에서는 자동으로 접을 수 있다.
- 화면을 전혀 가리지 않는 입력 패널은 불가능하므로, 내용 위에는 최소 면적만 사용한다. 별도 모니터가 있으면 패널 이동을 지원한다.
- 펜/영역 선택 중에만 필요한 입력을 받으며 Esc 또는 글로벌 단축키로 즉시 클릭 통과로 돌아간다.
- 펜 표시가 없어도 영역 캡처 가능. 전체 화면 전송은 별도 선택으로 둔다.
- 캡처 시점에 툴바/패널을 숨기고, 다중 모니터·DPI·화면 음수 좌표까지 검증한다.
- 질문 원문, 다듬은 문장, 실제 전송 문장을 구분해 저장한다. 다듬기 기본값은 끔이며 수동 버튼을 제공한다.
- 전송 전 로컬 기록 ID를 만들고 실패·취소·부분 응답을 보존한다. 재시도는 질문 복제 대신 별도 실행 기록을 추가한다.
- 세션 단위 대화를 지원한다. 캡처는 해당 메시지에 연결하고 이후 화면이 바뀌어도 기존 질문의 이미지를 바꾸지 않는다.

### 설정에서 기본 캡처 영역 편집

`설정 → 캡처 → 캡처 영역 설정`으로 전용 편집 화면을 연다.

1. 설정 창·툴바를 숨긴 뒤 대상 모니터 화면을 한 번 캡처해 고정 미리보기로 표시한다. 이때의 이미지는 설정용이며 질문 전송에는 사용하지 않는다.
2. 선택한 사각형 안쪽은 선명하게, 바깥쪽은 흐림과 옅은 어두운 마스크로 표시한다.
3. 박스 내부 드래그로 이동하고 네 모서리·네 변의 핸들로 크기를 조절한다. 경계와 가로×세로 크기를 표시한다.
4. `적용`, `취소`, `전체 화면`, `초기화`, 대상 모니터 선택을 제공한다. Enter로 적용, Esc로 취소하며 취소 시 이전 설정을 유지한다.
5. 적용한 영역을 이후 질문의 기본 캡처 범위로 사용한다. 매 질문에서는 현재 화면을 새로 캡처한 후 그 영역만 자른다.

- 흐림/마스크/핸들은 편집 UI에만 존재한다. 바깥 영역을 흐리게 포함해 전송하는 방식이 아니며 저장·전송 이미지에는 선택 범위 밖 픽셀을 포함하지 않는다.
- 기본 영역은 모니터별로 저장하고 전역/프로젝트 재정의를 지원한다. 일회성 질문 영역 선택은 기본 설정을 덮어쓰지 않는다.
- 영역은 모니터 ID, 모니터 기준 정규화 좌표와 설정 당시 화면 크기로 저장한다. 실제 캡처에서는 화면 DIP와 이미지 픽셀 배율을 변환하고 펜 좌표에도 같은 자르기 변환을 적용한다.
- 박스는 모니터 경계 안으로 제한하고 최소 크기를 둔다. 모니터가 사라지거나 화면 배치·해상도가 바뀌면 영역을 검증하고 재설정을 안내한다. 조용히 전체 화면으로 확장하지 않는다.
- 고정 영역 밖의 펜 표시는 잘리므로 입력 시 범위 경계와 안내를 제공한다. 자동으로 범위를 확장하지 않는다.
- 편집 미리보기는 종료 후 폐기한다. 실제 캡처 시에도 편집 UI와 질문 패널을 제외한다.

## 6. EasyCLIProxyAPI 로컬 endpoint 연결

사용자가 지정한 EasyCLIProxyAPI를 기본 연결 경로로 확정한다. 이전 초안의 FASK 자체 ChatGPT OAuth 및 Codex app-server 연결 검토는 초기 구현 범위에서 제외한다. 이는 로컬 HTTP 프로토콜로 요청하는 방식이며 실제 구독/공급자 인증은 프록시 쪽에서 완료한다.

```text
FASK → Electron main의 로컬 API 클라이언트
     → EasyCLIProxyAPI / CLIProxyAPI
     → 프록시에 연결된 공급자·계정·모델
```

### 설정 항목과 연결 동작

| 항목 | 동작 |
|---|---|
| 연결 이름 | 여러 endpoint를 구분하는 사용자 지정 이름 |
| Local API endpoint | EasyCLIProxyAPI Home에서 복사한 OpenAI 호환 Base URL. 예: `http://127.0.0.1:8317/v1`. 포트는 고정하지 않음 |
| 로컬 접속 키 | 프록시에 설정한 client API key. 공급자 API 키나 management key와 구분. 프록시가 요구하지 않을 때만 생략 |
| 연결 확인 / 모델 새로고침 | 인증·주소 확인 및 모델 목록 조회, 실패 원인 표시 |
| 기본 모델 | 조회된 모델 ID/별칭에서 선택, 필요 시 직접 입력 |
| 빠른 모델 / 깊은 추론 모델 | FASK 추천 정책에 사용할 모델 매핑 |
| 고급 설정 | Chat Completions 기본, 필요 시 Responses 선택·타임아웃 설정 |

- OpenAI 호환 endpoint 하나를 통해 연결된 여러 공급자 모델을 사용한다. 초기에는 Claude/Gemini 전용 프로토콜 어댑터를 별도로 만들지 않는다.
- 입력 주소 끝의 슬래시와 `/v1`을 정규화하고 `/v1/v1` 중복을 막는다. 완성된 `/chat/completions` 또는 `/responses` 주소를 붙여넣으면 Base URL과 프로토콜을 분리해 표시한다.
- 기본 계약은 `GET {baseUrl}/models`, `POST {baseUrl}/chat/completions`와 SSE 스트리밍이다. Responses는 지원되는 환경에서 선택한다. 이미지 메시지·스트림 이벤트는 선택 프로토콜에 맞춰 변환한다.
- 인증이 설정되어 있으면 로컬 접속 키를 Bearer 헤더로 전달한다. 인증 정보는 OS 보호 저장소에 보관하고 renderer·내보내기·로그에서 제외한다.
- 모델 목록의 ID/별칭을 그대로 보존한다. 목록 조회 성공과 실제 모델 추론 성공을 구분하고 이미지 지원은 별도 확인한다.
- 질문 다듬기·답변·분류는 같은 연결을 쓰되 모델을 다르게 지정할 수 있다. 프록시가 제공하지 않는 embedding/구조화 출력 기능을 가정하지 않는다.

### 책임 경계와 오류 처리

- FASK: 질문·기억·이미지·추천 모델·대화 이력·로컬 저장.
- EasyCLIProxyAPI: 공급자 로그인·토큰 갱신·상위 계정 선택·프록시 모델 별칭·프록시 내부 재시도/폴백.
- FASK는 관리 API나 공급자 토큰 파일을 읽지 않고 추론 API만 사용한다. 프록시를 설치·시작·설정 변경하는 작업도 초기 범위에 넣지 않는다.
- 프로필을 바꿔도 같은 프록시 endpoint/key를 쓰면 프록시에서는 같은 상위 계정 풀을 사용할 수 있다. 로컬 프로필과 공급자 계정의 일대일 연결을 가정하지 않는다.
- FASK는 요청한 모델과 응답에 드러난 모델을 저장한다. 상위 계정/실제 모델이 프록시에 숨겨지면 확인 불가로 표시한다.
- 프록시 미실행·연결 거부·401/403·모델 없음·429·타임아웃·응답 중단을 구분한다. 실행 안내 및 재시도 경로를 제공하고 질문·부분 답변은 보존한다.
- 프록시 목록에 유료 API 연결이 섞일 수 있으므로 endpoint만으로 구독 전용 사용을 보장하지 않는다. FASK는 허용 모델 목록을 사용하며 프록시 자체 계정/폴백 설정은 EasyCLIProxyAPI에서 관리한다.
- 기본 로컬 연결은 localhost/127.0.0.1/::1을 사용하고 다른 호스트는 별도 연결 설정으로 명시한다. 로컬 요청에서 다른 호스트로의 자동 리디렉션은 따르지 않는다.
- 대화 문맥은 FASK가 로컬에 관리한다. 이 연결로 기존 ChatGPT/Claude 대화를 자동 조회하거나 동기화한다고 가정하지 않는다.
- 실제 상위 공급자 지원 범위·이용 조건·구독 한도는 프록시 기능 설명만으로 보장하지 않는다. 설치된 코어와 연결 계정에서 검증한다.

0단계 완료 조건: endpoint/로컬 접속 키만으로 모델 조회, 텍스트/이미지 답변, 모델 전환, 스트리밍, 취소, 문맥 복원과 오류 처리를 확인한다. 실제 endpoint는 아직 제공되지 않았으므로 현재는 문서/소스 규격만 확인했다.

## 7. 질문 다듬기와 모델 추천 설정

| 설정 | 선택지 | 제안 기본값 |
|---|---|---|
| 질문 다듬기 | 끔 / 수동 / 자동 후 검토 | 끔 |
| 모델 선택 | 수동 / 추천 표시 / 자동 선택 | 추천 표시 |
| 지식 정리 | 수동 / 자동 연결 / 새 개념도 자동 제안 | 자동 연결 + 새 개념 제안 |
| 기억 사용 | 없음 / 현재 대화 / 관련 프로젝트 기록 | 관련 프로젝트 기록, 전송 범위 표시 |

추천은 연결되어 사용 가능한 모델만 대상으로 한다. 이미지·긴 문맥 등 필수 기능을 먼저 검사하고, 질문의 분석 단계·자료량·코드/수식·요구 작업을 고려한다. 단순히 문장 길이로 난이도를 정하지 않는다.

초기 라우터는 사용자가 지정한 빠른 모델/깊은 추론 모델 매핑과 로컬 규칙으로 동작한다. AI 판단은 선택적으로 추가한다. 판단 모델을 매번 호출하면 지연과 구독 한도를 추가 소비한다. 화면만으로 질문하거나 판단 근거가 약하면 `미확정`으로 두고 사용자 선택을 받는다.

저장 항목: 예상 복잡도(simple/complex/unknown), 판단 근거·방법·정책 버전, 추천 모델, 실제 모델, 사용자 변경. 복잡도·질문 유형·주제·보존 중요도는 서로 다른 필드다. 간단한 질문도 중요한 결정일 수 있다.

## 8. 데이터 모델과 저장

프로필별 SQLite 한 파일을 정본으로 사용하고 이미지는 별도 파일로 둔다. 그래프 DB와 별도 벡터 서버는 초기 범위에 필요하지 않다.

| 테이블 그룹 | 역할 |
|---|---|
| workspaces, projects | 분류 계층·설명·범위 |
| conversations, questions, messages | 대화·질문 원문/다듬기/전송 문장·답변·메모·출처 |
| runs, routing_decisions | 실행/재시도/공급자/모델/완료·실패·취소·추천 이력 |
| concepts, concept_relations | 프로젝트 내 개념과 방향/관계 유형 |
| question_concepts, question_relations | 질문의 다중 개념 연결, 후속/중복/관련 질문 |
| attachments, message_attachments | 이미지 해시·파일 위치·크기·정책·참조 |
| jobs, schema_migrations, settings | 중단 복구·스키마 버전·설정 |
| memory_items, memory_sources | 확인한 결정·요약·근거 질문·수정/폐기 상태 |

- 안정적인 ID와 UTC 시각, UI의 로컬 날짜 표시를 사용한다.
- 질문/답변은 원본 기록이고 그래프·요약·검색 인덱스는 파생 데이터다. 재생성해도 원본을 보존한다.
- 전체 텍스트 검색은 SQLite FTS5를 우선 검토한다. 한국어 부분 검색은 토크나이저/짧은 검색어의 제약을 확인하고 보완한다.
- 임베딩은 나중에 선택적으로 추가한다. 공급자·모델·차원·버전을 저장해 변경 시 재구축한다.
- 시작 시 스키마 버전 기반 마이그레이션을 수행한다. 현재 서버의 단순 누락 컬럼 추가 방식만으로는 전환할 수 없다.
- 백업은 SQLite 일관성 있는 스냅샷과 첨부 manifest를 함께 묶고 복원을 검증한다. 실행 중 DB 파일만 복사하지 않는다.
- 기존 학습 앱 DB는 덮어쓰지 않는다. 필요하면 별도 가져오기 도구에서 학생별 질문·메모·캡처를 선택 프로젝트에 복사하고 원본 ID를 남긴다.

## 9. 질문에서 성장하는 그래프

그래프 확장은 라우터의 전송 전 필수 단계로 두지 않는다. 답변 완료 또는 로컬 저장 뒤 별도 작업으로 처리한다. 다듬기가 꺼져도 원문·답변을 이용할 수 있다.

1. 새 프로젝트는 빈 상태와 미분류함으로 시작한다.
2. 질문마다 프로젝트 내부 기존 개념 후보를 검색한다.
3. 적합한 개념이 있으면 연결하고, 없으면 미분류에 둔 채 새 개념을 제안한다.
4. 답변까지 참고해 연결을 보완한다. AI를 쓸 수 없으면 미분류 상태에서도 검색·기록을 사용할 수 있다.
5. 새 개념 생성은 기본적으로 제안 후 반영한다. 완전 자동은 별도 옵션이다.
6. 사용자가 이름 변경·병합·분리·이동·연결 해제를 할 수 있다. 수동 수정은 잠그고 자동 정리가 덮어쓰지 않는다.

예: `개발 프로젝트 → Electron → 투명 창` 아래 질문을 모으고, 같은 질문을 `Windows 입력 처리`에도 연결한다. 트리에서는 대표 부모로 표시하고 관계 보기에서는 교차 연결을 보여준다. 트리의 부모 관계는 순환을 막고, 관련/비교 같은 관계는 순환을 허용할 수 있다.

질문마다 새 개념을 만들지 않는다. 동의어·기존 노드 ID·근거 질문·제안 신뢰도를 남기며 확신이 낮으면 보류한다. 질문 입력만으로 관련 지식 전체를 선제 생성하지 않는다.

간단한 질문과 복잡한 질문은 같은 저장 구조를 쓴다. 그래프에서는 간단한 질문을 개념의 질문 수로 접어 보여주고, 사용자가 펼치거나 중요 표시한 질문을 노출한다. 복잡도만으로 기록을 삭제하거나 기억에서 제외하지 않는다.

## 10. 대시보드

- 사이드바: 프로필 / 워크스페이스 / 프로젝트 / 검색 / 설정.
- 날짜순: 질문·답변·캡처·상태·복잡도·모델·태그, 날짜별 그룹.
- 주제별: 개념 트리와 관계 그래프, 미분류함, 수동 정리.
- 목록: 날짜·복잡도·주제·질문 유형·미해결·중요·이미지 유무 필터.
- 상세: 원문, 다듬은 문장, 실제 요청, 답변과 후속 대화, 이미지, 메모, 연결 개념, 출처.
- 복잡도 필터를 바꿔도 원본 기록은 유지한다. 검색 결과와 그래프에서 같은 질문 ID를 연다.
- 데이터가 커지면 전체 노드를 한 번에 그리지 않고 선택 개념 주변과 페이지 단위 질문을 표시한다.

## 11. 다른 ChatGPT/Claude 세션에서 기억 참조

1차 구현은 명시적으로 선택한 프로젝트/질문을 Markdown + JSON으로 내보내는 방식이다.

- `PROJECT_CONTEXT.md`: 프로젝트 목적, 용어, 확인된 결정, 미해결 질문, 관련 기록 ID·시각.
- `questions.jsonl`: 상세 원본 기록. 이미지 내보내기는 별도 옵션.
- `manifest.json`: 스키마 버전·생성 시각·대상 범위·첨부 목록.
- 바로 복사할 수 있는 짧은 문맥 묶음도 제공한다. 모든 과거 답변을 매번 넣지 않고 선택/검색한 근거만 담는다.
- AI 답변과 사용자가 확인한 결정을 구분하고, 변경·폐기된 기억과 원본 근거를 추적한다.
- 내보내기는 시점별 사본이다. 새 세션이 파일을 자동으로 읽거나 계속 갱신된다고 약속하지 않는다.

2차로 읽기 전용 MCP를 검토한다: 프로젝트 목록, 범위 내 검색, 질문 상세, 문맥 묶음 조회. 로컬 MCP를 지원하는 클라이언트에서는 로컬 연결을 사용한다. 웹/다른 기기의 세션은 로컬 프로세스에 바로 접근할 수 없으므로 해당 클라이언트 지원과 별도 인증 연결이 필요하다. 초기 앱 때문에 외부 공개 서버를 만들지 않는다.

## 12. 캡처 용량과 보존 정책

AI에 보낼 이미지의 품질과 디스크에 오래 보관할 이미지의 정책을 분리한다.

| 모드 | 저장 | 트레이드오프 |
|---|---|---|
| 최소 | 전송용 임시 이미지, 완료 후 제거 | 공간 절약, 나중에 시각 문맥 확인 불가 |
| 균형 | 선택 영역 압축 이미지 + 작은 썸네일 | 기본안. 글자·수식 가독성 확인 필요 |
| 보존 | 고해상도 영역, 선택 시 전체 화면 원본 | 재분석에 유리, 용량 증가 |

- 기본은 표시/선택한 영역과 여백만 저장한다. 캡처 원본과 펜 벡터를 기준으로 합성 이미지는 필요할 때 만든다.
- PNG/WebP 무손실/손실 후보를 텍스트·수식·사진 샘플로 비교해 형식과 크기를 정한다. 작은 글자를 무조건 축소하지 않는다.
- 보존 기간·용량 상한·중요 첨부 고정 설정을 제공한다. 초기에는 영구 삭제를 자동 활성화하지 않는다.
- 중복은 저장될 파일의 내용 해시로 제거하고 공유 참조가 남아 있으면 삭제하지 않는다.
- 실제 파일 크기 기준 프로젝트/전체 사용량과 정리 예상 확보량을 표시한다.
- 파일 제거 시 DB에는 첨부가 만료/제거되었다는 상태를 남긴다. 질문·답변과 로컬 추출 텍스트는 별도 보존한다. OCR 텍스트는 이미지를 완전히 대체하지 못한다.
- 전송 실패 시 재시도용 임시 파일과 폐기된 임시 파일을 구분하고 재시작 시 청소한다.
- 예산 예시: 하루 50건 × 300KB × 365일 ≈ 5.5GB/년, 같은 건수에 2MB면 ≈ 36.5GB/년. 실제 압축률 예측이 아닌 입력 크기별 계산이다.
- 정리 시 백업/내보내기에 같은 이미지가 남아 있을 수 있음을 사용량/삭제 범위에 반영한다.

## 13. 단계별 구현과 완료 기준

| 단계 | 구현 내용 | 완료 기준 |
|---|---|---|
| 0. 로컬 API 연결 검증 | EasyCLIProxyAPI endpoint/키 설정·모델 목록·텍스트/이미지·스트리밍·오류 검증 | FASK 자체 공급자 로그인 없이 연결. 설치 코어별 지원 범위 기록 |
| 1. 개인용 기반 | 프로필/워크스페이스/프로젝트, SQLite·마이그레이션, IPC, 개인용 진입 | 서버·로그인 없이 시작, 재시작 후 기록 유지, 프로필/프로젝트 분리 |
| 2. 질문과 답변 | 기존 오버레이 개편, 설정의 캡처 영역 편집·저장, 다듬기 생략, 로컬 API 연결, 스트리밍·취소·후속 대화 | 안쪽 선명/바깥 흐림 편집·박스 이동/크기 조절, 선택 영역만 전송, 답변과 실패 기록 복원 |
| 3. 대시보드 | 날짜순·목록·검색·상세·메모·복잡도 | AI 없이도 저장·검색·열람 가능 |
| 4. 지식 그래프 | 비동기 개념 연결·제안, 수동 편집, 다중 연결 | 빈 프로젝트에서 성장, 중복 억제, 수동 수정 보존 |
| 5. 추천과 보관 | 로컬 추천 정책·자동 선택 옵션·구독 한도 처리·이미지 정리 | 설정별 독립 동작, 실제 모델 이력, 유료 API 자동 전환 없음 |
| 6. 기억 공유와 패키징 | Markdown/JSON 내보내기·가져오기, 백업 복원, Windows 설치본 | 새 세션에 문맥 전달, 복원 후 첨부/검색 정상, Python 서버 없이 실행 |
| 후속 | 읽기 전용 MCP, 선택적 임베딩, 필요 시 추가 프로토콜, JEV 재검토 | 각 연결의 실제 지원 범위 확인 후 확장 |

첫 사용 가능한 버전의 목표는 0~3단계와 간단한 문맥 내보내기다. 이후 같은 저장 구조 위에 그래프와 자동화를 확장한다. 최종 목표에는 그래프와 추천 모두 포함된다.

검증 항목:

- 기존 UI를 바꾼 범위의 TypeScript 타입체크 및 앱 빌드.
- DB 마이그레이션·프로젝트 범위·중단 복구·백업 복원처럼 데이터 손실 가능성이 있는 경로의 집중 테스트.
- Windows 실기기에서 클릭 통과, 펜·지우개, Esc, 포커스 복귀, 다중 모니터/DPI, 캡처에서 툴바 제외, 작은 글자 가독성 확인.
- 캡처 영역 편집에서 이동·8방향 크기 조절·적용/취소·재시작 복원·모니터 분리/해상도 변경을 확인한다. 전송 파일에 바깥 영역·흐림 마스크·핸들이 들어가지 않고 펜 좌표가 일치하는지 확인한다.
- endpoint 입력 형식·`/v1` 중복 방지·인증 유무·모델 별칭·프록시 종료·부분 SSE·이미지 미지원 모델을 확인한다. 모델 목록 조회만으로 이미지 요청 성공을 판정하지 않는다.
- 공급자 실패·부분 응답·취소·인증 만료·한도 소진·앱 재시작에도 질문이 보존되는지 확인.
- 다듬기 끔/켬 × 모델 수동/추천/자동 × 지식 정리 수동/자동 조합의 핵심 동작 확인.
- 개인용 계약을 구체화할 때 `docs/PLAN.md`, renderer 타입, IPC 및 남겨두는 서버 계약의 적용 범위를 함께 문서화한다. 현재 계획서는 새 와이어 계약을 확정하지 않는다.

## 14. 근거와 미검증 사항

로컬 소스와 기존 `docs/PLAN.md`를 설계 기준으로 확인했다. 참조 채팅의 의도는 현재 화면을 펜으로 지정해 질문하는 흐름이며, 그 채팅의 제품 설명은 현재 공식 문서로 다시 확인한 내용과 구분했다. Git 명령은 실행하지 않았다.

현재 연결 설계의 직접 근거:

- [EasyCLIProxyAPI: 로컬 endpoint와 공급자 관리](https://github.com/router-for-me/EasyCLIProxyAPI)
- [CLIProxyAPI: API 라우트](https://github.com/router-for-me/CLIProxyAPI/blob/main/internal/api/server_routes.go)
- [CLIProxyAPI: 포트와 client API key 설정](https://github.com/router-for-me/CLIProxyAPI/blob/main/config.example.yaml)
